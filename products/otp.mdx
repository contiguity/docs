Contiguity offers a free OTP API that simplifies phone number verification using OTPs via SMS, which eliminates the need to develop custom logic. Gone are the days of paying for this simple feature.

<Warning>
    Contiguity still bills you for the text messages on our Usage tier, includes them in Unlimited, and subtracts them from your quota if you're on the Free tier. 
    
    We don't charge extra for the OTP API.
</Warning>

    ## Sending and Verifying OTPs
    <Steps>
    <Step title="Send an OTP">
        To verify a user's phone number, you'll first need to send them an OTP.

        ```typescript
        const res = await contiguity.otp.new({ 
            to: "+1234567890", 
            language: "en", 
            name: "MyApp" 
        });
        ```

        <Note>
          The `name` parameter is optional, but recommended. It customizes the message to say "Your [name] code is...", e.g. "Your Twilio code is..."
        </Note>
      </Step>

      <Step title="Verify the Code">
        When your user inputs the code, verify it using the OTP ID from the previous step.

        ```typescript
        const res = await contiguity.otp.verify({ 
            otp_id: "otp_123", 
            otp: "123456" 
        });
        ```

        <Note>
          The verification will return a boolean (true/false). OTPs expire 15 minutes after sending.
        </Note>
      </Step>

      <Step title="Resend if Needed">
        If needed, you can resend an OTP using the original OTP ID.

        ```typescript
        const res = await contiguity.otp.resend({ 
            otp_id: "otp_123" 
        });
        ```

        <Note>
          Resending an OTP does not renew its expiry time.
        </Note>
      </Step>
    </Steps>

    ## Parameters

    ### otp.new(params)

    <ParamField body="to" type="string" required>
      The recipient's phone number in E.164 format (e.g., "+1234567890").
    </ParamField>

    <ParamField body="language" type="string" required>
      The language code for the OTP message. See supported languages below.
    </ParamField>

    <ParamField body="name" type="string" required>
      The name of your application or service. This will be included in the OTP message as "Your [name] code is...".
    </ParamField>

    ### otp.verify(params)

    <ParamField body="otp_id" type="string" required>
      The unique OTP identifier returned from the `otp.new()` call.
    </ParamField>

    <ParamField body="otp" type="string" required>
      The 6-digit verification code entered by the user.
    </ParamField>

    ### otp.resend(params)

    <ParamField body="otp_id" type="string" required>
      The unique OTP identifier from the original `otp.new()` call.
    </ParamField>

    ## Reverse OTP

    Reverse OTP verifies a phone number by having the user send a code to you. Start a session with `otp.reverse.initiate()`:

    ```javascript
    const session = await contiguity.otp.reverse.initiate({
        number: "+1234567890",
        service: "sms"
    });
    ```

    The `service` can be `"sms"` or `"imessage"` and defaults to `"sms"`. Using iMessage requires an active iMessage-capable leased number and an iMessage entitlement.

    Check the session's status or cancel it using the returned `otp_id`:

    ```javascript
    const status = await contiguity.otp.reverse.verify(session.otp_id);
    await contiguity.otp.reverse.cancel(session.otp_id);
    ```

    ### otp.reverse.initiate(params)

    <ParamField body="number" type="string" required>
      The expected sender's phone number in E.164 format.
    </ParamField>

    <ParamField body="factor" type="string">
      The code or phrase the user sends. It can contain up to 16 characters and defaults to a random four-digit code.
    </ParamField>

    <ParamField body="to" type="string">
      The number the user sends the code to. It defaults to a random Contiguity-owned number. When using iMessage, provide an iMessage-capable number leased through Contiguity.
    </ParamField>

    <ParamField body="service" type="string" default="sms">
      The messaging service used to receive the code. Accepts `"sms"` or `"imessage"`.
    </ParamField>

    <ParamField body="language" type="string" default="en">
      The language code used for the returned UI instructions.
    </ParamField>

    <ParamField body="success_url" type="string">
      A webhook URL called after successful verification. If omitted, Contiguity uses your configured webhook preferences.
    </ParamField>

    #### Response

    <ResponseField name="otp_id" type="string">
      The Reverse OTP session ID used to check or cancel the session.
    </ResponseField>

    <ResponseField name="number" type="string">
      The expected sender's phone number.
    </ResponseField>

    <ResponseField name="factor" type="string">
      The code or phrase the user must send.
    </ResponseField>

    <ResponseField name="to" type="string">
      The number the user must message.
    </ResponseField>

    <ResponseField name="service" type="string">
      The messaging service receiving the code: `"sms"` or `"imessage"`.
    </ResponseField>

    <ResponseField name="expires_at" type="string">
      The session expiration time in ISO 8601 format.
    </ResponseField>

    <ResponseField name="ui" type="object">
      Localized `text` instructions and a `qr_code` payload for opening the user's messaging app.
    </ResponseField>

    <ResponseField name="success_url" type="string | null">
      The webhook URL used for successful verification.
    </ResponseField>

    <ResponseField name="metadata" type="object">
      Request metadata including ID, timestamp, and API version.
    </ResponseField>

    ### otp.reverse.verify(otp_id)

    <ParamField body="otp_id" type="string" required>
      The Reverse OTP session ID returned by `otp.reverse.initiate()`.
    </ParamField>

    #### Response

    <ResponseField name="otp_id" type="string">
      The Reverse OTP session ID.
    </ResponseField>

    <ResponseField name="status" type="string">
      The session's current status: `"pending"`, `"verified"`, `"cancelled"`, or `"expired"`.
    </ResponseField>

    <ResponseField name="expires_at" type="string">
      The session expiration time in ISO 8601 format.
    </ResponseField>

    <ResponseField name="metadata" type="object">
      Request metadata including ID, timestamp, and API version.
    </ResponseField>

    ### otp.reverse.cancel(otp_id)

    <ParamField body="otp_id" type="string" required>
      The Reverse OTP session ID returned by `otp.reverse.initiate()`.
    </ParamField>

    #### Response

    <ResponseField name="otp_id" type="string">
      The cancelled Reverse OTP session ID.
    </ResponseField>

    <ResponseField name="status" type="string">
      Confirms that the session was cancelled.
    </ResponseField>

    <ResponseField name="metadata" type="object">
      Request metadata including ID, timestamp, and API version.
    </ResponseField>

    See the [Reverse OTP API reference](/api-reference/product/otp/reverse/initiate) for API behavior, or learn more about [Reverse OTP with iMessage](/api-reference/product/imessage/verify).

    ## Sending and Verifying OTPs
    <Steps>
    <Step title="Send an OTP">
        To verify a user's phone number, you'll first need to send them an OTP.

        ```python
        otp_id = client.otp.send({
            'to': "+15555555555",
            'language': "en",
            'name': "Contiguity"
        })
        ```

        <Note>
          The `name` parameter is optional, but recommended. It customizes the message to say "Your [name] code is...", e.g. "Your Twilio code is..."
        </Note>
      </Step>

      <Step title="Verify the Code">
        When your user inputs the code, verify it using the OTP ID from the previous step.

        ```python
        verify = client.otp.verify({
            'otp_id': otp_id,  # from the previous step
            'otp': input       # the 6 digits your user inputted
        })
        ```

        <Note>
          The verification will return a boolean (true/false). OTPs expire 15 minutes after sending.
        </Note>
      </Step>

      <Step title="Resend if Needed">
        If needed, you can resend an OTP using the original OTP ID.

        ```python
        resend = client.otp.resend({
            'otp_id': otp_id  # from the first step
        })
        ```

        <Note>
          Resending an OTP does not renew its expiry time.
        </Note>
      </Step>
    </Steps>
